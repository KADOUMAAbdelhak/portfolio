OSR — Ontology Semantic Reasoner

Full-stack semantic deployment integration within the AC3 CECCM framework

Overview

OSR (Ontology Semantic Reasoner) is a major software component within the AC3 CECCM framework. It connects end-user application requirements, semantic application information, catalogue and data-source information, and cloud-edge deployment workflows.

In practical terms, OSR helps transform higher-level requirements into deployment-oriented outputs suitable for Kubernetes-based environments. Semantic information and associated data-source details are part of that translation flow, so operators receive machine-readable deployment definitions instead of having to assemble them manually.

The Problem

Cloud-edge deployment workflows need structured application requirements and machine-readable deployment information. End users should not have to manually translate high-level needs into low-level Kubernetes deployment definitions.

OSR bridges that gap by processing semantic application information and integrating with other AC3 components—particularly catalogue and data-source services—so requirements can be mapped into deployment-oriented representations. The implementation focuses on producing deployable Kubernetes manifests with associated data-source information, without claiming fully autonomous end-to-end deployment of the wider AC3 platform.

What OSR Does

OSR sits between user-facing requirement capture and deployment-oriented outputs. A simplified view of the flow:

1 End-user requirements

Capture application needs through the OSR interface

2 OSR frontend & backend

Full-stack processing in Node.js services and UI

3 Semantic application information

Structure and interpret application metadata

4 Piveau Hub / GraphQL

Catalogue and interoperability integration

5 Profiles & data sources

Persist profiles and attach data-source information

6 Kubernetes manifests

Produce deployable cloud-edge deployment definitions

Architecture / Data Flow

OSR combines a user-facing frontend with Node.js backend services. Semantic application information is processed and exchanged with catalogue infrastructure through Piveau Hub via GraphQL. Application profiles are stored in MySQL/MariaDB, while authentication-related storage uses SQLite. The resulting outputs are Kubernetes-oriented deployment manifests that include associated data-source information for cloud-edge deployment workflows.

Requirements → OSR (UI + Node.js) → Semantic metadata → Piveau Hub (GraphQL) → Profiles / data sources → Kubernetes manifests

Supporting semantic interoperability technologies in this context include DCAT-AP, Gaia-X concepts, and SHACL-based validation where they contribute to consistent catalogue and metadata exchange.
