DaaruNaim School

School Website & Admissions Platform

Full-Stack Web Platform DaaruNaim School

Overview

This project is a production web platform for Daaru Na'im Academy / Daaru Na'im Schools. It provides a modern public-facing school website together with a structured digital admissions application workflow.

The system combines school information and public content with guardian registration and login, multi-child application drafts, document uploads, submission and receipts, administrative review, admissions decisions, and notifications. It is deployed as a production web application on the school’s public domain.

The Problem

The school needed more than a static website. The platform had to support both public-facing school information and structured digital admissions workflows.

  • Making school information easy to access
  • Allowing guardians to manage applications online
  • Handling multiple children and applications
  • Securely handling private documents
  • Preserving submitted applications
  • Giving administrators a structured review workflow
  • Providing clear application status and decision communication

The Solution

The platform delivers a public school website and an end-to-end admissions experience.

Public website capabilities include school profile and history, mission and vision, learning methods, activities, school life, daily programme, admissions information, and contact details.

Admissions capabilities include guardian account registration and login, multiple child applications, draft saving, document uploads, declaration and submission, submission receipts, administrative review, decisions, office-use information, internal notes, and notifications.

Architecture

At a public level, the system follows a straightforward full-stack deployment model:

Frontend → FastAPI backend → PostgreSQL / object storage → containerised deployment behind Nginx

The stack includes FastAPI, PostgreSQL, a Vite frontend, Docker / Docker Compose, MinIO for object storage, an Nginx reverse proxy, cookie-based sessions, CSRF protection, and notification outbox / email-delivery integration.

Admissions Workflow

  1. Guardian creates an account
  2. Guardian completes child application details
  3. Supporting documents are uploaded
  4. Application remains editable while in draft
  5. Guardian submits with declaration
  6. Submission is locked and receipt generated
  7. Administrator reviews the application
  8. Decision/status is recorded
  9. Guardian receives updated information/notifications

Engineering Considerations

Data Integrity

Submitted applications are preserved so later changes cannot silently alter the submitted record.

Privacy

Application documents remain private and access-controlled.

Workflow State

Draft, submission, review, and decision stages are represented explicitly.

Reliability

Containerised services, database persistence, health-aware deployment, and production debugging support stable operation.

Security

Authenticated sessions, CSRF protection, private file handling, and HTTPS support safer production operation.
